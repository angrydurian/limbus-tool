# 데이터 입력 도구 (깃허브 이슈 양식)

2026-11-27 추가. 저장소 **Issues → New issue**에서 양식을 골라 내용을 넣고 제출하면, 자동 처리(Actions)가 데이터에 넣고 결과를 댓글로 남긴다. 휴대폰 깃허브 앱에서도 된다.

## 양식

| 양식 | 넣는 것 | 반영되는 곳 |
|---|---|---|
| 기프트 추가·수정 | 위키 글(여러 개 이어 붙여도 됨), 아이콘 캡처(글의 기프트 순서대로), 아이콘 대상 이름(선택), 팩 지정(선택, `기프트 이름 = 팩 이름`) | `gifts/gifts.json`, `gifts/icons/`, `gifts/gifts.md` |
| 인격·E.G.O 추가·수정 | Claude가 캡처로 만든 JSON(`{"identity":..}`/`{"ego":..}`, 여러 개 가능) 또는 사이트 '변경분 복사' JSON | `data/db/identities.json`, `egos.json`, `recs.json` |

- 아이콘만 바꿀 때: 위키 글은 비우고 캡처 + '아이콘 대상 이름'만 넣는다.
- 인격·E.G.O 사진은 여전히 Claude 채팅으로 보내 JSON을 받는다(사진 → 글자는 자동 처리하지 않음).

## 자동 처리 순서 (`.github/workflows/intake.yml` → `tools/intake.py`)

1. 저장소 주인이 낸, 열린 이슈이고 라벨이 `기프트 입력` 또는 `인격·E.G.O 입력`일 때만 돈다. 이슈를 만들 때·고칠 때·다시 열 때 실행.
2. 기프트: `parse_gifts.py` → 캡처를 받아 `add_icon.py` → `set_pack.py` → 검사 → `make_md.py`.
   인격·E.G.O: JSON 문법 → 검사 → `apply_pending.py`.
3. 검사
   - 기프트: 등급·가격·기본 효과가 있어야 함. 캡처 수 = 대상 기프트 수. 없는 기프트 이름이면 실패. 아이콘 없음·조합 재료 없음은 참고로만 알림.
   - 인격: name, 12수감자 중 하나인 sinner, rarity 1~3, S1·S2·S3 스킬, 알려진 slot만.
   - E.G.O: name, sinner, grade(ZAYIN~ALEPH), cost `[["죄악",개수]]`, awaken, res 값(취약/보통/내성/견딤).
   - `uncertain`이 비어 있지 않으면 실패(값을 확인해 채우고 비운다).
   - id가 없고 같은 수감자·이름이 이미 있으면 그 항목을 고친다. 새 항목이면 `c-`/`e-` + 시간 id.
4. 통과 → main에 `데이터: ... (#이슈번호)` 커밋, 결과 댓글, 이슈 닫음. 바뀐 게 없으면 커밋 없이 닫음.
   실패 → 커밋 없음, 이유 댓글, `확인 필요` 라벨. 이슈 내용을 고쳐 저장하면 다시 처리.
5. 사이트에는 다음 버전 때 들어간다(`tools/embed_db.py`, `tools/embed_gifts.py`).

## 고칠 때

- 양식 칸 이름을 바꾸면 `tools/intake.py`의 `LABELS`도 같이 바꾼다(본문을 `### 칸 이름`으로 나눠 읽음).
- 로컬 시험: `python3 -I tools/intake.py gift|db 본문.md 결과.md` (저장소 맨 위에서. 데이터 파일이 실제로 바뀌니 시험 뒤 `git checkout .`).
