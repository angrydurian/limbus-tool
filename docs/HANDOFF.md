# 림버스 컴퍼니 통합 툴 — 작업 인계 문서

작성: 2026-10-02 · 이전 작업: claude.ai 채팅 (v0 ~ v1.2, E.G.O 시험판 v0.2)

## 1. 프로젝트 개요

림버스 컴퍼니용 통합 웹 툴. 최종 목표는 편성 빌더, 합·데미지 계산기, 거울 던전 기프트 도우미, 재화·추출 계획표 네 기능을 하나로 합치는 것. 현재는 **편성 빌더**를 만드는 중.

- 형태: 단일 HTML 파일, 모바일 호환 반응형 웹페이지
- 공유 전제: 인격 데이터는 공용(관리자만 쓰기), 편성은 사용자별 저장
- 관리자: 지금은 소유자(한수)만. 판단 기준은 "페이지 편집 권한"이라 나중에 편집 권한을 주면 관리자가 늘어남

## 3. 작업 규칙 (사용자 선호)

1. **요구사항을 먼저 정리하고, 사용자가 명시적으로 승인한 뒤에 코드를 만든다.** "~하는 게 좋을 것 같아"는 승인이 아니다. 의견을 주면 수정 사항으로 적어두고 확인을 받는다.
2. **버전별 백업을 남긴다.** 2026-11-02부터는 파일을 복제하지 않고 git 커밋으로 남긴다. 버전 커밋은 메시지 첫 줄을 `v0.2: ...`처럼 시작하고, 가능하면 같은 이름의 태그도 단다(클라우드 세션에서는 태그 푸시가 막힐 수 있음). 이전 버전은 태그로 언제든 되돌릴 수 있어야 한다.
3. **공개 링크는 하나를 유지한다.** 새 버전을 새 링크로 올리면 저장 공간(편성, 관리자가 넣은 인격)이 따로 생겨 데이터가 사라진 것처럼 보인다. 반드시 기존 링크를 업데이트한다.
4. 사용자는 수정 사항을 모아서 한 번에 반영하는 걸 선호한다 ("한번에 하자").
5. **새 버전을 만들면 테스트 후 바로 본 프로그램 링크까지 업데이트하고 알린다** (2026-10-06 요청: "항상 만들고 바로 링크 업데이트까지 완료하고 나한테 말해줘"). 링크 업데이트 여부를 따로 묻지 않는다. 단 1번(코드 전 요구사항 승인)은 그대로 지키고, 테스트가 실패하면 올리지 않고 보고한다.

## 5. 데이터 구조

### 5.1 인격 (4동기화 기준만 저장)

```
{id, sinner, name, rarity(1|2|3), season("통상"|"1"|...), traits[], release, ticket, keywords[],
 src("capture"|"wiki"),
 stats:{hp, spd:[min,max], def, defBonus},
 res:{"참격":["취약",2], "관통":["보통",1], "타격":["내성",0.5]},
 stagger:[15,35,65],
 skills:[{slot:"S1"|"S2"|"S3"|"DEF"|"S1x"|"S2x"|"S3x"|"DEF2"|"EX", name, lv, bonus, type, sin, qty(3|2|1|null),
          base, cp, w, coins, fx:[스킬 전체 효과], cf:[{n:코인번호, fx:[효과]}], note?, unbreakable?,
          by?: 실제로 쓰는 수감자(없으면 본인), requires?: [{sinner, name}]}],   // v2.6 편성 조건부 스킬
 // v2.3: S1x/S2x/S3x = 강화 스킬 1·2·3, DEF2 = 강화 수비 (특정 조건을 만족하면 기본 스킬 대신 나가는 스킬). qty null, note에 발동 조건.
 //       죄악 개수 계산에는 기본 S1~S3만 들어감. 같은 칸의 강화 스킬이 여러 개여도 됨.
 //       EX는 예전(v2.2까지) "강화 스킬" 표기. 화면엔 "강화 스킬 (칸 미정)"으로 보이고, 양식에서 1·2·3·수비 중 다시 골라야 저장됨
 passive:{name, sin, count, cond:"공명"|"보유", desc[], reqs?:[[죄악,개수],...]},
 // v2.4: 조건 죄악이 2개 이상이면 reqs에 전부(모두 만족해야 발동), sin·count는 항상 첫 번째 값. 1개면 reqs 없음
 support:{같은 형식},
 always:[{name, desc[]}],   // 조건 없는 상시 패시브
 sanity:null | {gain[], loss[]}}   // null = 기본 정신력 조건과 같음
```

- 수비 유형: 가드, 회피, 반격, 강화 방어, 강화 반격
- 레벨 표기 "65(0)" → lv 65, bonus 0. 수비 스킬 레벨은 화면 값을 그대로 믿는다 (공격 스킬 기준 공식과 안 맞을 수 있음)
- 코인 수는 스킬 이름 위 점 개수. 코인별 효과의 로마 숫자가 코인 번호. 번호 없는 효과는 fx, 번호 있는 효과는 cf
- (v2.7에서 삭제) 나무위키에서 옮긴 `src:"wiki"` 히스클리프 인격 7개는 사용자 요청으로 페이지에서 뺐음. 데이터가 필요하면 v2.6 이하 파일에 남아 있음. 화면의 "위키 출처" 표시 코드는 남아 있지만 해당 데이터가 없어 보이지 않음
- 기본 인격 12개(LCB)는 게임 캡처 기준으로 검증 완료, 페이지에 내장(`LCB` 배열)

### 5.2 E.G.O (v2.0에서 구현, 실제 데이터는 아직 없음)

```
{id("e-..."), sinner, grade:"ZAYIN"|"TETH"|"HE"|"WAW"|"ALEPH", name, base(고유 여부),
 cost:[[죄악, 개수], ...], sanity(정신력 소모), lv(공격 레벨),
 res:{분노..질투: "취약"|"약점"|"보통"|"견딤"|"내성"},   // v2.8 견딤(×0.75), v2.9 약점(×1.5) 추가
 awaken:{name, type(참격|관통|타격), sin, base, cp, w, coins, fx[], cf[]},
 awaken2?:{동일},                     // 두 번째 각성 스킬 (있을 때만)
 corrosion:{동일} | null(고유 E.G.O), corrosion2?:{동일},
 passive:{name, desc[], extra?:[{requires:[{sinner,name}], desc[]}]},   // v3.0 extra = 특정 인격 편성 시에만 보이는 효과
 t5: 5해석 가능 여부, t5data:{awaken, awaken2?, corrosion, corrosion2?, passive} | null}
```

- 페이지 내장 E.G.O는 `EGO_BUILTIN` 배열(지금은 비어 있음). db `egos`가 그 위에 덮어씀
- t5data에는 5해석 값 전체를 저장(달라지지 않은 부분 포함). 화면은 5해석일 때 t5data에 있는 항목만 덮어씀
- 고유 E.G.O는 수감자당 하나만 허용(양식에서 검사)

- 4해석이 기본. 5해석 있는 E.G.O만 5단계 데이터를 추가 저장하고, 편성에서 E.G.O별로 토글
- 고유 E.G.O는 침식 스킬 없음, ZAYIN 등급으로 취급
- 오버클록(자원·정신력 1.5배)은 공통 규칙이라 저장 안 함
- E.G.O는 인격이 아니라 수감자에 붙는다. 인격을 바꿔도 장착 E.G.O 유지

### 5.3 런타임 저장 공간 (db)

- `identities/{id}`: `{data: 인격, deleted: bool, updatedAt, updatedBy}` — 페이지 내장 데이터(`BUILTIN`) 위에 덮어씀. `deleted:true`면 숨김
- `egos/{id}` (v2.0): `{data: E.G.O, deleted, updatedAt, updatedBy}` — 인격과 같은 방식
- `drafts/{id}`: `{identity, uncertain[], existingId?, createdAt, by}` — 검토 대기. E.G.O는 `{kind:"ego", ego, uncertain[], existingId?, createdAt, by}`
- `history/{id}`: `{identityId, name, at, by, changes[], before(JSON 문자열)}` — 되돌리기용. E.G.O는 `{kind:"ego", egoId, ...}` (kind가 없으면 인격 기록)
- `data/users/{uid}/decks`: `{decks: {편성이름: {pick:{수감자:인격id}, order:[수감자...], equip:{수감자:{등급:egoId}}, t5:{egoId:true}}}}` — 사용자별 편성, 기기 간 동기화. equip/t5가 없는 예전 편성은 불러올 때 ZAYIN 고유만 채움
- 비로그인 사용자: db 없음 → 내장 데이터만 보이고 편성은 브라우저에만 저장
- 기본 제공 편성 `TEST`(기본 인격 12명, 수감자 번호 순)는 페이지에 내장, 삭제·덮어쓰기 불가

## 6. 지금까지 확정된 화면 결정

- 편성: 빈 번호 칸 누르면 다음 순번, 번호 있는 두 칸을 차례로 누르면 자리 교환, 같은 칸 두 번 누르면 빠짐. 1–7번 출격, 8–12번 대기 (최신 콘텐츠 기준 7명 출격 + 5명 대기)
- 스킬 패: 스킬 1·2·3 한 칸씩, 큰 죄악 아이콘 타일
- 분석 패널 "홈": 출격 인원이 얻는 죄악 개수(스킬 1·2·3 수량 3·2·1장 합산, 대기 제외) + 패시브 발동 점검(출격=전투 패시브, 대기=서포트 패시브)
- 인격을 누르면 분석 패널이 그 인격의 상세(스킬, 코인별 효과, 순번에 맞는 패시브)로 바뀜
- 인격 선택 창: 이름 검색, 등급(전체·0·00·000), 키워드 필터. 등급 높은 순 정렬
- 효과 문장 속 키워드 앞에 아이콘 자동 표시 (`ICONS`, 긴 이름 우선 매칭, 예외는 `KW_NOT` 예: "광신도"의 "광신" 제외). 밝은 테마 보완 `PALE`, 어두운 테마 보완 `DARKI`
- 관리자 탭: 데이터 붙여넣기(JSON) → 검토 양식. 양식은 노란 칸(확인 필요)이 남거나 범위 오류가 있으면 확정 불가, 기존 인격 수정 시 바뀌는 항목을 먼저 보여주고 한 번 더 눌러야 저장
- 페이지 내 이미지 AI 변환은 코드가 있지만, 크롬과 데스크톱 앱 모두 플랫폼이 이미지 전송을 지원하지 않아 숨겨짐. 텍스트 변환은 동작하며, 텍스트 입력 시 패시브 조건 죄악·코인 수·코인별 배정을 자동으로 "확인 필요" 처리

### v2.0에서 추가로 확정된 화면 결정 (2026-10-02 승인)

- 편성 탭 위에 단계 표시 `1 인격 · 2 E.G.O · 3 최종본`. 단계 표시를 눌러도 이동
- 분석 패널은 1페이지와 3페이지 모두에 보임(같은 패널을 옮겨 붙임)
- 편성 불러오기는 1페이지 위쪽에도 있음. 저장·삭제는 3페이지
- E.G.O 표는 12명 모두 보이고, 편성에 없는 수감자 줄은 흐리게. 데이터 없는 칸은 "데이터 없음"(누를 수 없음)
- E.G.O를 고르면 선택 창이 닫힘(v0.2 동작 유지). "다음 등급/수감자"는 고르지 않고 다음 칸으로 이동
- 3페이지 "최종 편성": 순번대로 수감자·인격·장착 E.G.O 이름·5해석 여부. 비용 합계 같은 분석은 넣지 않음. 인격을 누르면 분석 패널이 그 인격 상세로
- 관리자 탭: "E.G.O 데이터 붙여넣기" 패널, "E.G.O 목록"(수정·삭제) 패널. E.G.O 선택 창의 "자세히"에도 관리자용 "수정" 버튼
- E.G.O 양식: "고유 E.G.O" 체크 시 등급 ZAYIN으로 바뀌고 침식 스킬 칸 숨김. "두 번째 각성/침식 스킬 있음" 체크로 칸 추가. "5해석 있음" 체크 시 4해석 값을 복사한 5해석 칸이 열림("4해석 값 다시 복사" 버튼)

### v2.1 결정 (2026-10-06 승인)

- 관리자 탭 "데이터 붙여넣기"(인격·E.G.O 모두): 확인 필요 칸이 없고, 양식과 같은 입력 검사에 오류가 없고, 새 데이터이며, 같은 수감자에 같은 이름(공백 무시)이 없으면 **양식 없이 바로 저장**. 수정 기록에 "신규 추가 (바로 저장)"으로 남아 되돌리기 가능

## 7. v2 작업 범위 (승인된 계획 · v2.0 파일로 구현 완료, 사용자 확인 대기)

1. **3페이지 편성 흐름**: 1페이지 인격 설정(인격 + 순번) → "다음" → 2페이지 E.G.O 표 → "완료" → 3페이지 최종본(분석, E.G.O 현황, 저장, 1·2페이지로 돌아가기)

4. **관리자 탭에 E.G.O 입력**: 인격과 같은 붙여넣기 + 검토 양식(노란 칸, 범위 검사, 수정 기록, 되돌리기). 5해석 데이터도 같은 양식에서
5. 편성 저장 형식에 E.G.O 장착(`equip:{수감자:{등급:egoId}}`)과 5해석 토글 상태 추가. 기존 저장 편성과 호환 유지

## 10. 캡처 → 데이터 변환 안내문 (사용자가 채팅에 붙여넣는 용도)

캡처는 인격당 두 장: ① 기본 정보·스테이터스·내성 ② 흐트러짐 구간부터 코인별 효과를 펼친 스킬·패시브. 변환 결과는 관리자 탭 "데이터 붙여넣기"에 넣는다.

```
림버스 컴퍼니 인격 캡처를 읽어서, 내 편성 도구의 관리자 탭 '데이터 붙여넣기'용 JSON으로 만들어줘. 규칙:
- 4동기화 기준. 안 보이거나 확실하지 않은 값은 추측하지 말고 null로 두고 그 키를 uncertain에 넣기.
- 스킬 이름 위 점 개수 = coins. 코인별 효과 앞 로마 숫자(Ⅰ,Ⅱ…) = 코인 번호.
  가장 큰 번호가 점 개수보다 크거나, 코인이 여러 개인데 효과가 앞쪽 코인에만 있으면 "S2.coins"처럼 uncertain에 넣기.
- 번호 없는 효과는 fx(스킬 전체), 번호 있는 효과는 cf:[{"n":번호,"fx":[문장]}]. 문장은 화면 그대로.
- "65(0)"은 lv 65, bonus 0. qty는 S1=3, S2=2, S3=1, DEF=null. DEF의 w는 화면에 "-"면 null.
- res는 {"참격":["취약",2],"관통":["보통",1],"타격":["내성",0.5]} 형식.
- 정신력 조건이 기본(합 승리 비례 증가 / 적 처치 10 / 아군 처치 5 / 아군 사망 레벨 차 감소)과 같으면 sanity:null,
  다르면 {"gain":[문장],"loss":[문장]}.
- keywords는 효과에 나오는 상태 키워드(화상, 출혈, 진동, 파열, 침잠, 호흡, 충전 등).
- 조건 없는 상시 패시브는 always:[{"name","desc":[문장]}], 없으면 [].
- 패시브 조건 죄악이 여러 개면(모두 만족해야 발동) sin과 count를 같은 순서의 배열로:
  "sin":["나태","우울","오만"],"count":[1,1,1]. 하나면 "sin":"분노","count":3.
- skills의 slot: 기본 스킬은 "S1","S2","S3","DEF". 특정 조건을 만족하면 기본 스킬 대신 나가는 강화 스킬은
  "S1x","S2x","S3x"(강화 스킬 1·2·3), "DEF2"(강화 수비). 강화 스킬은 qty:null, 발동 조건을 note에 적기
  (예: "적진 주파 5일 때 스킬 3 대신 발동"). 같은 칸의 강화 스킬이 여러 개면 같은 slot으로 여러 개 넣어도 됨.
  강화 스킬 slot 정하는 법(이 경우 uncertain에 넣지 않음):
  · "EX"나 기본 slot("S3" 등) 중복은 쓰지 않는다.
  · 수비 유형(가드/회피/반격/강화 방어/강화 반격)이면 "DEF2".
  · 공격 스킬이면 효과 문장에 "스킬 N 대신", "'○○'로 발동됨" 같은 근거가 있는 칸으로, 근거가 없으면 죄악 속성이 같은 기본 스킬 번호로.
  · note(발동 조건)는 선택 항목. 화면에 보이면 적고, 안 보이면 note를 빼고 uncertain에도 넣지 않는다.
  · 강화 스킬도 lv·bonus·type·sin·base·cp·coins·w를 기본 스킬처럼 채운다(강화 수비의 w가 "-"면 null).
- uncertain에는 화면에서 정말 읽을 수 없는 값만 넣는다(추측해서 채운 값만 해당).
- 다른 인격이 편성에 있어야만 나오는 스킬은 그 스킬 항목에 "requires":[{"sinner":"이상","name":"N사 E.G.O::흉탄"}]
  (적힌 인격이 모두 편성에 있어야 함), 이 인격이 아닌 다른 수감자가 실제로 쓰는 스킬이면 "by":"이상". 해당 없으면 두 키를 넣지 않기.
  확인 필요 키는 S3x.by, S3x.requires처럼.
- uncertain 키는 아래 이름만 쓰기(다른 이름은 노란 칸으로 표시되지 않음):
  name, sinner, rarity, season, traits, release, ticket, keywords, hp, spd, def, res, stagger, sanity,
  S1.name/S1.lv/S1.type/S1.sin/S1.base/S1.cp/S1.w/S1.coins/S1.fx/S1.cf (S2, S3, DEF, S1x, S2x, S3x, DEF2도 같은 방식,
  강화 스킬은 S3x.slot·S3x.note도 가능), P.name/P.sin/P.count/P.cond/P.desc(전투 패시브), SP.name/SP.sin/SP.count/SP.cond/SP.desc(서포트 패시브).
- id는 넣지 말고(기존 인격 수정이면 "existingId"에 기존 id), 인격마다 JSON 하나씩 코드 블록으로만 출력.
형식: {"identity":{...5.1의 인격 구조...},"uncertain":[]}
```

## 11. E.G.O 캡처 → 데이터 변환 안내문 (v2.0, 관리자 탭 "E.G.O 데이터 붙여넣기"용)

> **최신판은 `EGO-변환-안내.md` (2026-10-20, v2.7 코드 기준으로 검증)**. 다른 Claude 채팅에 이 파일을 통째로 올려서 쓴다. 아래 짧은 안내문은 예전 버전 기록용.
> 코드에서 확인한 함정: `res` 값이 취약/보통/내성이 아니면 오류 없이 "보통"으로 저장됨, `cost`를 객체로 쓰면 비용이 비어 오류.

캡처는 E.G.O당 4해석 화면(기본 정보·비용·내성, 각성·침식 스킬의 코인별 효과, 패시브). 5해석이 있으면 5해석 화면도 함께 올린다.

```
림버스 컴퍼니 E.G.O 캡처를 읽어서, 내 편성 도구의 관리자 탭 'E.G.O 데이터 붙여넣기'용 JSON으로 만들어줘. 규칙:
- 4해석 기준. 안 보이거나 확실하지 않은 값은 추측하지 말고 null로 두고 그 키를 uncertain에 넣기.
- grade는 ZAYIN/TETH/HE/WAW/ALEPH. 수감자 고유 E.G.O면 base:true, grade "ZAYIN", corrosion:null.
- cost는 [["분노",2],["질투",1]]처럼 죄악과 개수. sanity는 정신력 소모, lv는 공격 레벨.
- res는 7죄악 각각 "취약"|"보통"|"내성": {"분노":"보통","색욕":"취약",...}.
- awaken(각성)·corrosion(침식) 스킬은 {"name","type"(참격/관통/타격),"sin","base","cp","w","coins","fx":[문장],"cf":[{"n":번호,"fx":[문장]}]}.
  스킬 이름 위 점 개수 = coins, 코인별 효과 앞 로마 숫자 = 코인 번호. 번호 없는 효과는 fx. 각성·침식 스킬이 두 개면 두 번째는 awaken2/corrosion2.
- passive는 {"name","desc":[문장]}.
- 5해석 캡처가 있으면 t5:true, t5data:{"awaken","corrosion","passive"}에 5해석 값 전체(달라지지 않은 부분 포함). 없으면 t5:false, t5data:null.
- uncertain 키: name, sinner, grade, base, cost, sanity, lv, res, A.name/A.type/A.sin/A.base/A.cp/A.w/A.coins/A.fx/A.cf
  (A=각성, A2=각성2, C=침식, C2=침식2, P.name/P.desc=패시브, 5해석은 앞에 "T." 예: T.A.base, T.P.desc).
- id는 넣지 말고(기존 E.G.O 수정이면 "existingId"에 기존 id), E.G.O마다 JSON 하나씩 코드 블록으로만 출력.
형식: {"ego":{...5.2의 E.G.O 구조...},"uncertain":[]}
```
