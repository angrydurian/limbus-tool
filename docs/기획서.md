## 1. 개요

림버스 컴퍼니 유저가 게임에서 보기 어려운 정보(키워드, 기프트, 인격·E.G.O 상세)를 찾고, 편성·보유 관리 같은 반복 작업을 줄이도록 돕는 통합 플랫폼이다. 게임과 같은 편성 코드를 읽고 만들 수 있는 것이 핵심 차별점이다.

| 항목 | 내용 |
| --- | --- |
| 목적 | 게임에 부족한 정보를 보여 주는 라이브러리 + 게임 편의를 돕는 도우미를 하나로 합친 플랫폼 |
| 사용자 | 림버스 컴퍼니 유저 (일반 방문자), 데이터를 관리하는 관리자 1명 이상 |
| 플랫폼 | React 기반 웹 페이지 (HTML). PC와 휴대폰 브라우저 모두 지원 |
| 운영 | claude.ai 공개 링크 하나로 운영. 소스는 GitHub `angrydurian/limbus-tool`에서 관리. 수정은 다음 버전 브랜치의 PR에 모았다가 버전을 올릴 때 main에 합친다 |
| 데이터 출처 | 게임 화면 캡처, 나무위키, 게임 편성 코드 분석 |

## 2. 현재 상태 (v0.4)

핵심 기능 4개 중 편성 코드·보유 확인·관리자 분리는 동작하고, 라이브러리는 키워드만 화면에 있고 기프트는 데이터만 모인 상태다. 지금은 React가 아닌 단일 HTML 파일(순수 JavaScript)로 만들어져 있다.

| 기능 | 상태 | 비고 |
| --- | --- | --- |
| 편성 3단계 (인격 → E.G.O → 최종본) | 완료 | 저장·불러오기, 죄악 분석 포함 |
| 게임 편성 코드 불러오기·만들기 | 완료 | 샘플 6개 왕복 변환 글자 단위 일치, 실제 게임 입력 확인은 남음 |
| 추천 덱 (관리자 올리기, 방문자 불러오기) | 완료 | 투표는 미구현 |
| 내 보유 (인격·E.G.O, 동기화·해석 단계) | 완료 | 로그인 시 기기 간 동기화 |
| 키워드 창·툴팁 | 완료 | 394개 중 설명 342개, 52개 비어 있음 |
| 기프트 라이브러리 | 데이터 수집 중 | 236개 저장(아이콘 전부, 팩 전용·저주/축복·히든 포함), 화면 미구현 |
| 관리자 탭 (캡처 → 데이터 변환) | 완료 | 인격 190개, E.G.O 111개 입력됨 |
| 비로그인 공유·백업 코드 | 미구현 | 다음 작업 묶음 |

## 3. 핵심 기능

핵심 기능은 4개다. 이 4개가 5장의 완성 기준을 모두 통과하면 플랫폼을 완성한 것으로 본다.

### 3-1. 덱 편성과 게임 편성 코드

- 수감자 12명의 인격·편성 순번(출격 7 + 대기 5)·E.G.O(ZAYIN~WAW, ALEPH는 출시 후)를 고른다.
- 게임에서 복사한 편성 코드(`H4sI…`)를 붙여 넣으면 그대로 편성이 구성된다.
- 도구에서 짠 편성을 게임 편성 코드로 만들어 복사한다.
- 다른 유저의 덱: 관리자가 올린 추천 덱과, 유저끼리 보낸 편성 코드를 바로 불러온다.
- 편성 분석: 죄악 자원 분포, 패시브 발동 여부, 키워드 구성.
- 편성 저장·불러오기 (로그인 시 기기 간 동기화).

### 3-2. 보유 확인

- 인격·E.G.O마다 보유 / 미보유, 인격 동기화 단계(1~4), E.G.O 해석 단계(4/5)를 기록한다.
- 수감자별·전체 보유율을 보여 준다.
- 편성 선택 창의 "보유만 보기", 추천 덱의 "없는 인격·E.G.O 수"에 쓰인다.
- 개인 데이터는 사람마다 따로 저장하고, 다른 사람에게 보이지 않는다.

### 3-3. 라이브러리

- **인격·E.G.O**: 스킬, 패시브, 내성, 출시일. 수감자·죄악·키워드·등급 필터. 시너지(같은 계열 출격 인원에 따른 팀 효과)도 표시한다 (v0.5 예정).
- **키워드**: 설명, 분류(기본/범용/고유), 그 키워드를 쓰는 인격·E.G.O 목록, 스킬 글의 툴팁.
- **거울 던전 E.G.O 기프트**: 단계(Ⅰ~Ⅴ, EX), 지원 키워드, 가격, 획득처(통상/합성/한정), 강화 효과(+/++), 조합식, 아이콘. 팩 전용(여러 팩 가능), 저주→축복 짝과 바뀌는 조건, 히든 보스 기프트(시즌이 지나면 약화되는 효과)도 구분한다.
- 검색과 필터로 원하는 항목을 찾는다.

### 3-4. 관리자 권한 분리

- 공용 데이터(인격, E.G.O, 추천 덱, 기프트)는 모두 읽고 **관리자만 쓴다.**
- 관리자 화면과 입력 버튼은 관리자에게만 보인다.
- 화면에서 버튼을 숨기는 것뿐 아니라, 저장 공간 규칙으로 일반 사용자의 쓰기를 막는다.
- 변경 기록(history)을 남겨 잘못 고친 데이터를 되돌릴 수 있다.

## 4. 추가(+) 기능

추가 기능은 완성 기준에 들어가지 않고, 구현 가능한 범위까지 넣는다. 위에서부터 우선순위다.

| 순위 | 기능 | 내용 | 필요한 것 |
| --- | --- | --- | --- |
| 1 | 비로그인 공유 | 로그인하지 않은 사람도 인격·E.G.O·추천 덱·기프트를 본다 (데이터를 페이지에 내장) | 공개 링크 가능 여부 확인 |
| 2 | 백업 코드 | 보유·편성을 글자 코드로 내보내고 다른 기기에서 불러온다 | 없음 |
| 3 | 기프트 우선도 | 덱 키워드에 맞는 기프트를 추천하고 획득 우선순위를 보여 준다 | 우선도 기준 합의 |
| 4 | 합성표·진행 체크리스트 | 합성 재료와 현재 모은 기프트를 표시한다 | 기프트 데이터 완성 |
| 5 | 추천 덱 투표 | 방문자 투표로 목록 순서를 정한다 | 저장 공간 규칙 추가 승인 |
| 6 | 합·데미지 계산기 | 스킬끼리 합 승률과 피해량을 계산한다 | 계산식 정리 |
| 7 | 재화·추출 계획표 | 재화와 추출 계획을 세운다 | 재화 종류·확률 자료 |

## 5. 객관적 완성 기준

아래 항목을 모두 만족하면 완성이다. 각 항목은 누가 확인해도 같은 결과가 나오도록 숫자나 통과/실패로 정했다. 테스트는 자동 브라우저 테스트(playwright)와 실제 게임 확인으로 한다.

| 기능 | 합격 조건 | 확인 방법 | 현재 |
| --- | --- | --- | --- |
| 편성 코드 불러오기 | 게임에서 복사한 코드 10개 이상을 불러왔을 때 12명의 인격·순번·E.G.O가 게임 화면과 100% 일치 | 게임 화면 캡처와 비교 | 샘플 7개 일치 |
| 편성 코드 만들기 | 도구가 만든 코드 5개를 게임에 넣었을 때 모두 같은 편성으로 들어감 | 실제 게임에 입력 | 미확인 |
| 코드 왕복 | 불러온 코드를 다시 만들면 원래 코드와 글자 단위로 같음 | 자동 테스트 | 통과 (6/6) |
| 게임 번호 커버리지 | 저장된 인격·E.G.O의 100%에 게임 번호가 있음 (출시 첫날 동률 포함) | 번호표 자동 점검 | 첫날 인격 11명분 미확정 |
| 추천 덱 | 관리자가 올린 덱을 다른 계정에서 열어 불러오기·코드 복사가 됨 | 두 계정으로 확인 | 실계정 미확인 |
| 보유 기록 | 보유·동기화·해석 단계가 새로고침 후에도 유지 | 자동 테스트 | 통과 |
| 보유 동기화 | 같은 계정의 PC와 휴대폰에서 같은 보유 현황이 보임 | 두 기기로 확인 | 미확인 |
| 보유 분리 | 다른 계정에서 내 보유·편성이 보이지 않음 | 두 계정으로 확인 | 구조상 분리됨 |
| 인격·E.G.O 라이브러리 | 현재 출시된 인격·E.G.O의 100%가 등록되고 상세 창이 열림 | 나무위키 목록과 개수 비교 | E.G.O 5개 빠짐 |
| 키워드 라이브러리 | 키워드 394개 전부 설명이 있고, 툴팁이 PC·휴대폰에서 뜸 | 자동 점검 + 테스트 | 설명 342/394 |
| 기프트 라이브러리 | 나무위키 기프트 목록의 100% 등록, 검색·키워드·단계·획득처 필터 동작, 합성 재료가 모두 등록됨 | 목록 개수 비교 + 자동 점검 | 236개, 팩 전용 수집 중, 화면 없음 |
| 관리자 쓰기 차단 | 관리자가 아닌 계정의 공용 데이터 쓰기가 100% 거부됨 | 낮은 권한으로 쓰기 시도 | 통과 (추천 덱 확인) |
| 관리자 화면 숨김 | 관리자가 아닌 계정에 관리자 탭·입력 버튼이 보이지 않음 | 다른 계정으로 확인 | 구현됨 |
| 화면 품질 | 휴대폰 폭(390px)에서 가로 넘침 0건, 자바스크립트 오류 0건 | 자동 테스트 | 통과 |

추가(+) 기능은 "동작하는 만큼 넣기"가 기준이다. 넣은 기능은 위와 같은 화면 품질 기준(넘침 0건, 오류 0건)을 통과해야 한다.

## 6. 기술 구조와 데이터

데이터는 세 곳에 나눠 저장하고, 저장 위치마다 쓸 수 있는 사람을 정해 관리자 권한을 분리한다. (구조 그림은 claude.ai 기획서 문서에 있음)

| 항목 | 내용 |
| --- | --- |
| 화면 | React 컴포넌트로 화면을 나눔. 라이브러리는 cdnjs의 UMD 빌드로 불러옴 (별도 서버 없음) |
| React 전환 | 지금은 순수 JavaScript. 화면 단위로 하나씩 옮기고, 옮길 때마다 기존 자동 테스트를 통과해야 다음으로 넘어감 |
| 공용 데이터 | identities, egos, recs (기프트 추가 예정): 읽기 누구나, 쓰기 관리자 |
| 관리자 전용 | drafts(변환 초안), history(변경 기록): 읽기·쓰기 모두 관리자 |
| 개인 데이터 | `data/users/{본인ID}/decks`, `owned`: 본인만 읽고 씀 (사이트 주인도 못 봄) |
| 원본 데이터 | GitHub: `keywords/keywords.json`, `gifts/gifts.json`, `data/game-numbers.json`, 아이콘 PNG |
| 게임 코드 | base64(gzip(base64(70바이트))). 수감자 12명 × 46비트: 인격 번호 8 · 순번 4 · E.G.O 7×4 · ALEPH 6 |

## 7. 개발 순서와 위험 요소

기프트 데이터와 빠진 번호를 먼저 채우고, 그다음 화면을 만든 뒤 React로 옮긴다. 단계마다 5장의 해당 기준을 통과해야 다음으로 간다.

1. **데이터 채우기**: 기프트 나머지(팩 전용), 키워드 설명 52개, 빠진 E.G.O 5개, 출시 첫날 인격 번호 11명분
2. **기프트 라이브러리 화면**: 검색·필터·상세·조합식 표시. 같은 버전(v0.5)에 인격·E.G.O 시너지 칸도 넣음
3. **비로그인 스냅샷 + 백업 코드**: 계정 없는 유저에게 공개
4. **게임 확인**: 만든 코드 5개 게임 입력, 두 계정·두 기기 확인
5. **React 전환**: 화면 단위로 옮기며 자동 테스트 유지
6. **추가(+) 기능**: 4장 순위대로

| 위험 | 영향 | 대응 |
| --- | --- | --- |
| 게임 업데이트로 편성 코드 형식이 바뀜 | 불러오기·만들기가 깨짐 | 샘플 코드 자동 테스트로 바로 확인, 형식은 인계 문서에 기록 |
| 신규 인격·E.G.O가 게임 번호를 밀어냄 | 코드가 다른 인격을 가리킴 | 번호를 출시일로 계산, 새 데이터는 출시일 필수 |
| ALEPH E.G.O 출시 | ALEPH 칸 구조 미확정 | 출시 후 샘플 코드 1개로 확정 |
| 공개 링크가 막힘 (저장 공간 기능 때문) | 계정 없는 유저가 못 봄 | 저장 기능을 빼고 스냅샷만 담은 공개용 페이지를 따로 둠 |
| 나무위키 자동 접속 차단 | 데이터 자동 갱신 불가 | 글자 복사 → 변환 스크립트로 수동 갱신 |
| React 전환 중 기존 기능 깨짐 | 서비스 품질 하락 | 화면 단위 전환, 테스트 통과 전에는 올리지 않음 |
